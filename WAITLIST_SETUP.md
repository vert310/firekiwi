# Waitlist Setup Instructions

## 1. Install Dependencies

The required packages are already in `package.json`. Run:

```bash
npm install
```

## 2. Set Up Supabase Database (Free & Easy!)

1. Go to [Supabase.com](https://supabase.com) and sign up/login (it's free!)
2. Click **"New Project"**
3. Fill in:
   - **Name**: `firekiwi` (or any name)
   - **Database Password**: Create a strong password (save it!)
   - **Region**: Choose closest to you
   - **Pricing Plan**: Free tier is perfect
4. Click **"Create new project"** (takes ~2 minutes)

## 3. Create the Waitlist Table

Once your project is ready:

1. Go to **SQL Editor** in the left sidebar
2. Click **"New query"**
3. Paste this SQL:

```sql
CREATE TABLE IF NOT EXISTS waitlist (
  id BIGSERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Create an index for faster email lookups
CREATE INDEX IF NOT EXISTS idx_waitlist_email ON waitlist(email);
```

4. Click **"Run"** (or press Cmd/Ctrl + Enter)
5. You should see "Success. No rows returned"

## 4. Get Your Supabase Credentials

1. Go to **Settings** (gear icon) → **API**
2. You'll see:
   - **Project URL** (looks like: `https://xxxxx.supabase.co`)
   - **Project API keys** section
   - Copy the **`service_role`** key (not the `anon` key - we need the service role for server-side operations)

## 5. Set Up Resend for Emails

1. Go to [Resend.com](https://resend.com) and sign up/login
2. Go to **API Keys** section
3. Create a new API key
4. Copy the API key

### 5a. Add DNS Records to Your Domain (Namecheap)

**Where do the DNS records come from?**

When you add your domain (`firekiwi.com`) to Resend, Resend **automatically generates** the DNS records you need. Here's how:

1. **In Resend Dashboard:**
   - Go to **Domains** section
   - Click **"Add Domain"** or **"Verify Domain"**
   - Enter your domain: `firekiwi.com`
   - Resend will automatically generate:
     - The DNS record names (like `resend._domainkey`)
     - The DNS record values (long strings for DKIM/SPF authentication)
   
2. **Why `resend._domainkey`?**
   - This follows the **DKIM (DomainKeys Identified Mail)** standard
   - Format: `[selector]._domainkey`
   - Resend uses `resend` as the selector (without underscore prefix)
   - The `_domainkey` part is required by the DKIM standard
   - **You don't create this** - Resend generates it automatically when you add your domain

3. **What you need to do:**
   - Copy the DNS records that Resend shows you
   - Add them to your domain's DNS settings (Namecheap in this case)
   - Wait for DNS propagation
   - Resend will verify the records are correct

**Important**: You cannot customize or change the DNS record names - they're automatically generated by Resend based on email authentication standards (DKIM, SPF, DMARC).

To verify your domain in Resend and enable sending emails from your domain, you need to add DNS records in Namecheap:

To verify your domain in Resend and enable sending emails from your domain, you need to add DNS records in Namecheap:

1. **Log in to Namecheap**
   - Go to [namecheap.com](https://www.namecheap.com)
   - Click **"Sign In"** in the top right corner
   - Enter your username and password

2. **Navigate to Domain List**
   - After logging in, click on **"Domain List"** in the left sidebar (or go to: https://ap.www.namecheap.com/domains/list/)
   - You'll see a list of all your domains

3. **Select Your Domain**
   - Find **firekiwi.com** in the list
   - Click on the **"Manage"** button next to it

4. **Access DNS Settings**
   - In the domain management page, look for the **"Advanced DNS"** tab
   - Click on **"Advanced DNS"** (it's usually the second tab)

5. **Add the TXT Record**
   - Scroll down to the **"Host Records"** section
   - Look for the **"TXT Records"** section (or find an **"Add New Record"** button)
   - Click **"Add New Record"** button
   - In the record form:
     - **Type**: Select **"TXT Record"** from the dropdown
     - **Host**: Enter the name exactly as Resend shows it (without your domain suffix)
       - If Resend shows Name: `resend._domainkey`, enter: `resend._domainkey`
       - If Resend shows Name: `@` or just your domain, enter: `@`
       - **Important**: Do NOT add `.firekiwi.com` - Namecheap automatically appends your domain
       - **Important**: You cannot change this name - it's set by Resend for DKIM verification
     - **Value**: Paste the long string value that Resend provides (this is the DKIM/SPF record)
       - Copy the entire value string from Resend (it's usually very long)
     - **TTL**: Leave as default (usually "Automatic" or "30 min")
   - Click **"Save All Changes"** (green checkmark icon) or **"Save"** button

6. **Verify the Record**
   - The new TXT record should now appear in your DNS records list
   - Double-check that the Host and Value match exactly what Resend provided
   - **Note**: The record name (like `resend._domainkey`) is set by Resend and cannot be customized. This is part of the DKIM standard for email authentication. You must use exactly what Resend provides.

7. **Wait for DNS Propagation**
   - DNS changes can take 5-10 minutes to propagate, but sometimes up to 24-48 hours
   - You can check propagation status using tools like:
     - [whatsmydns.net](https://www.whatsmydns.net)
     - [dnschecker.org](https://dnschecker.org)
   - In Resend, you can check the domain verification status - it will show as "Verified" once DNS has propagated

8. **Additional Records (if needed)**
   - Resend may require multiple records (SPF, DKIM, DMARC)
   - Repeat steps 5-6 for each record Resend provides
   - Make sure to use the exact Host and Value for each record

**Note**: If you're using Namecheap's BasicDNS, you may need to switch to Namecheap's PremiumDNS or use a custom nameserver. Most domains work fine with BasicDNS for TXT records.

### 5b. Create an Email Address for Your Domain (e.g., onboarding@firekiwi.com)

There are two scenarios for creating an email address:

#### Option A: Sending Emails FROM Your Domain (Recommended for Resend)

If you just want to **send emails** from `onboarding@firekiwi.com` (which is what Resend does), you don't need to create an actual email inbox. Once your domain is verified in Resend (after completing step 5a), you can use any email address on your domain:

1. **In Resend Dashboard:**
   - Go to **Domains** section
   - Verify that your domain shows as "Verified" (green checkmark)
   - Once verified, you can send emails from any address like:
     - `onboarding@firekiwi.com`
     - `noreply@firekiwi.com`
     - `hello@firekiwi.com`
     - etc.

2. **Update Your Environment Variable:**
   - In Vercel → **Settings** → **Environment Variables**
   - Update `RESEND_FROM_EMAIL` to: `onboarding@firekiwi.com` (or `FireKiwi <onboarding@firekiwi.com>`)
   - Save and redeploy

**Note**: This only allows SENDING emails. You won't receive emails sent TO this address.

#### Option B: Receiving Emails TO Your Domain (Full Email Hosting)

If you want to **receive emails** at `onboarding@firekiwi.com` (have an actual inbox), you need email hosting. Here are options:

**Option B1: Namecheap Private Email (Easiest)**

1. **Log in to Namecheap**
   - Go to [namecheap.com](https://www.namecheap.com) and sign in

2. **Navigate to Domain List**
   - Click **"Domain List"** in the left sidebar
   - Find **firekiwi.com** and click **"Manage"**

3. **Set Up Private Email**
   - Look for **"Private Email"** section or tab
   - Click **"Create Email Account"** or **"Get Private Email"**
   - Choose a plan (usually starts around $1-2/month per mailbox)
   - Create the email address: `onboarding`
   - Set a password for the email account
   - Complete the purchase/setup

4. **Access Your Email**
   - Namecheap will provide you with:
     - Webmail URL (usually `https://privateemail.com`)
     - IMAP/POP3 settings if you want to use an email client
   - Log in with `onboarding@firekiwi.com` and your password

**Option B2: Google Workspace (More Features)**

1. Go to [workspace.google.com](https://workspace.google.com)
2. Sign up for Google Workspace (starts at $6/month per user)
3. Verify your domain ownership
4. Create `onboarding@firekiwi.com` user
5. Access via Gmail interface or any email client

**Option B3: Microsoft 365 (Business Email)**

1. Go to [microsoft.com/microsoft-365](https://www.microsoft.com/microsoft-365)
2. Choose a plan (starts around $6/month)
3. Add your domain and verify
4. Create the `onboarding@firekiwi.com` mailbox

**Recommendation**: For most use cases with Resend, **Option A is sufficient** - you only need to send emails, not receive them. Only choose Option B if you actually need to receive emails at that address.

## 6. Configure Environment Variables in Vercel

1. Go to your Vercel project → **Settings** → **Environment Variables**
2. Add these variables:

   **Supabase:**
   - `NEXT_PUBLIC_SUPABASE_URL` = Your Supabase Project URL (from step 4)
   - `SUPABASE_SERVICE_ROLE_KEY` = Your Supabase service_role key (from step 4)

   **Resend:**
   - `RESEND_API_KEY` = Your Resend API key
   - `RESEND_FROM_EMAIL` = Your sender email
     - For testing: `onboarding@resend.dev`
     - For production (after domain verification): `onboarding@firekiwi.com` or `FireKiwi <onboarding@firekiwi.com>`

3. Make sure to add these for **Production**, **Preview**, and **Development** environments
4. Click **Save**

### 6a. Resend vs Vercel: Which is the Source of Truth?

**Resend is the source of truth** for what email addresses you can actually send from.

**How it works:**
- **Resend** verifies your domain and controls which email addresses are allowed
- **Vercel** stores the `RESEND_FROM_EMAIL` environment variable that your application reads
- Your application uses the value from Vercel, but Resend validates it when sending

**If there's a mismatch:**

1. **Resend allows it, but Vercel has different value:**
   - ✅ Update Vercel to match what Resend allows
   - Example: Resend verified `firekiwi.com` → You can use `onboarding@firekiwi.com`
   - Update Vercel's `RESEND_FROM_EMAIL` to `onboarding@firekiwi.com`

2. **Vercel has it, but Resend doesn't allow it:**
   - ❌ Emails will fail to send
   - Example: Vercel has `onboarding@firekiwi.com` but domain isn't verified in Resend
   - Solution: Verify your domain in Resend first (step 5a), then update Vercel

3. **Both have different values:**
   - ✅ Always trust Resend's domain verification status
   - Update Vercel to match what Resend allows
   - Check Resend dashboard → Domains → Verify domain shows "Verified"

**Best practice:**
1. First verify your domain in Resend (step 5a)
2. Wait for domain verification to complete
3. Then update Vercel's `RESEND_FROM_EMAIL` to match an email on your verified domain
4. Redeploy your Vercel application

**To check what Resend allows:**
- Go to Resend dashboard → **Domains**
- If your domain shows "Verified" ✅, you can use any email address on that domain
- If it shows "Pending" or "Failed" ❌, you cannot use emails from that domain yet

## Troubleshooting

- **Email not sending**: Check Resend API key and from email are correct
- **Database errors**: Ensure Supabase credentials are correct and table is created
- **404 on API route**: Make sure you've deployed the latest code to Vercel
- **"Email already registered"**: This is working correctly - it prevents duplicates!
